# Nick identicon + color

A small deterministic identicon square is drawn next to a nick everywhere the
UI shows one (message rows, the members inspector). It is paired with the
same palette-index-derived tint used for the nick's text color. Both the
bitmap and the color are fully deterministic from client-visible inputs — no
client hashes a nick itself for color; the palette index always comes from
the server. This doc is the client-agnostic spec: implement a new client from
this doc, not by reading another client's source.

Conforming implementations:

- Web: `web/src/nick.ts` (`nickAvatar`), `web/src/nick-palette.ts`, `web/src/format.ts` (`nickColor`)
- Apple (macOS/iOS): `apple/Lurker/NickAvatar.swift`

## Palette index origin

The nick→color mapping is computed **server-side** by the Go `nickcolor`
package, keyed by the lowercased nick (case-insensitive). The server ships a
palette index (`0`–`47`, or `null`/absent for "not yet known") on every
nick-bearing payload:

- `Message.sender_color` / `Message.target_color`
- member list entries' `color` field
- `Network.nick_color` (the client's own nick)

Clients cache the last-seen index per (lowercased) nick and look it up at
render time; they never hash nicks themselves. A `null`/missing index (index
not yet observed for that nick) renders as gray, both for the avatar tint and
the nick text color.

## Color: hue, lightness, chroma

```
NICK_HUES[i] = i * 7.5   for i in 0..47   (0°, 7.5°, 15°, ..., 352.5°)
hue = NICK_HUES[index % 48]
```

`web/src/nick-palette.ts` is generated by `task gen-palette`
(`scripts/gen-nick-palette.mjs`) from this formula — 48 perceptually-spaced
OKLCH hues, evenly 7.5° apart.

Tint color is `oklch(L C hue)` with defaults `L=0.72`, `C=0.12`. Unknown index
(`null`) renders gray: `oklch(L 0 0)` (same L, chroma 0, hue irrelevant).

L and C are themeable on the web client: theme YAML sets `nicks.oklch_l` /
`nicks.oklch_c`, applied as CSS custom properties `--nick-l` / `--nick-c`
(see [theming.md](theming.md)). Other clients (Apple, TUI) hardcode the
defaults `L=0.72`, `C=0.12` and do not currently read theme YAML for this.

### OKLCH → sRGB conversion

`H` is in degrees; `L` and `C` as above. This is the standard CSS Color 4
OKLab-based conversion:

```
h = H * pi/180
a = C*cos(h)
b = C*sin(h)

l_ = L + 0.3963377774*a + 0.2158037573*b
m_ = L - 0.1055613458*a - 0.0638541728*b
s_ = L - 0.0894841775*a - 1.2914855480*b

l = l_^3
m = m_^3
s = s_^3

R =  4.0767416621*l - 3.3077115913*m + 0.2309699292*s
G = -1.2684380046*l + 2.6097574011*m - 0.3413193965*s
B = -0.0041960863*l - 0.7034186147*m + 1.7076147010*s

gamma(c) = c <= 0.0031308 ? 12.92*c : 1.055*pow(c, 1/2.4) - 0.055
```

Apply `gamma` to each of R, G, B, then clamp to `[0, 1]`. The web client
instead emits raw `oklch(...)` CSS values and lets the browser do this
conversion; native clients (Apple, TUI) must implement it directly since
their frameworks don't parse OKLCH.

## Bitmap: xorshift32 identicon

A 5×5 grid, mirrored left/right, generated by a small deterministic PRNG
(xorshift32) seeded from the nick's raw (NOT lowercased) characters. All
arithmetic is unsigned 32-bit (`>>> 0` semantics in JS terms — implementers
in other languages must use an unsigned 32-bit integer type, or explicitly
mask to 32 bits after every op, so shifts and wraparound match JS exactly).

**Seeding** — iterate the nick's UTF-16 code units (`String.charCodeAt` in
JS; `String.utf16` in Swift) in order, starting from `r = 1`:

```
r = 1  (uint32)
for each UTF-16 code unit ch of the raw nick:
    r = r + ch          (wrapping add, mod 2^32)
    r ^= r << 13         (mod 2^32)
    r ^= r >>> 17         (logical/unsigned right shift)
    r ^= r << 5           (mod 2^32)
```

**Bitmap generation** — 5×5 grid, `size = 5`, `half = floor(size / 2) = 2`.
Row-major: `y` outer loop `0..4`, `x` inner loop `0..half` (i.e. `0..2`
inclusive — only the left half plus the center column is generated; the
right half is filled by mirroring). For each cell, first advance the PRNG one
round, then test the low bit to decide fill:

```
for y in 0..4:
    for x in 0..2:
        r ^= r << 13
        r ^= r >>> 17
        r ^= r << 5
        if (r % 2) == 1:        # equivalently r & 1 == 1
            fill(x, y)
            fill(size - 1 - x, y)   # mirror onto the right half
```

Note the center column (`x = 2`, mirror target `4 - 2 = 2`) mirrors onto
itself — filling it once is a no-op the second time, not a double-fill bug.

Cells that are not filled render transparent (no background fill), so the
identicon shows through the surrounding UI. Filled cells render in the same
tint as the nick's palette color (`nickPaletteColor(index)` — see above);
unknown index renders gray, same as the nick text.

any conforming implementation must reproduce them exactly for these nicks:

```

#.#.#             .#.#.             .###.             ##.##             ##.##
```
